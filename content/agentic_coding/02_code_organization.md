Singleness of responsibility, step of concerns, two sides of same coin for different levels - sing is functions - don't make them too long but also can be bad to make too short, step is for organizing the repo - so config files (one of them) and pulling general code out into properly names spaces, top down programming builds on all of this, functionality flows from most general to most specific in stack, orchestration code stays together and sep from shuttling capabilities and string management and eval code and training code and etl stuff but those last two are similar enough to be in their own directory for example (function dim vs generalization dim) - also try not to rewrite pandas - make sure agents know where things go so they don't dry and adhere to flow so it's obvious where to point for building and debugging - not too deep directory trees - easily take it from batch to real time or add a stage to model architecture or make two similar models run in parallel (trying out new ideas, iterating, shipping quickly can get super complex to track if you don't do these things - eventually prohibitively slow - whole point of agentic is fast so don't fuck this up)
